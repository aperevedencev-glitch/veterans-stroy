# Терминал члена СРО (FlowLink)

Клиентский терминал к роботу [«ЕИС → сверка → НОСТРОЙ»](../flowlink-robot-eis-nostroy). Член СРО «Стройкорпорация» входит по ИНН и коду доступа, видит только свои договоры из ЕИС и отвечает по каждому: «Да, наш», «Не наш» или «Исправить» (верные цена и дата). Можно добавить договор, которого робот не нашёл.

## Как устроено

- `index.html` — страница терминала, работает на GitHub Pages, сборка не нужна.
- Серверная функция Supabase `sro-terminal` — единственная точка доступа к данным. Таблицы `sro_members`, `sro_contracts`, `sro_responses` закрыты RLS: браузер напрямую их не читает.
- Код доступа у каждого члена свой, в базе хранится только его хеш с солью. После 8 неверных попыток за час вход по этому ИНН закрывается на час.
- Оператор СРО забирает ответы в роботе по ключу оператора (действие `op_responses`).

## Действия функции

| Действие | Кто | Что делает |
|---|---|---|
| `login` | член СРО (ИНН + код) | его договоры и прошлые ответы |
| `respond` | член СРО | сохраняет ответы `yes / no / fix / new` и почту для связи |
| `op_responses` | оператор (`x-op-key`) | все ответы после даты `since` и почты членов |
| `op_import` | оператор | загружает членов и договоры из `flowlink-robot-eis-nostroy/data/members.json` |

## Рассылка кодов

Коды доступа не хранятся в репозитории. Оператор получает их отдельным файлом и рассылает членам СРО вместе со ссылкой на терминал. Чтобы выдать новый код, нужно пересчитать хеш в `sro_members` (код в открытом виде нигде не сохраняется).

## Файлы

- `supabase/functions/sro-terminal/index.ts` — серверная функция (развёрнута в проекте Supabase, `verify_jwt = false`, проверка по коду и ключу оператора внутри).
- `supabase/migrations/20261020_sro_terminal_init.sql` — таблицы и запрос для перевыпуска кода одному члену.

## Обновление данных

Договоры в терминале берутся из `flowlink-robot-eis-nostroy/data/members.json`. После обновления файла оператор вызывает `op_import` (или повторяет загрузку через SQL) — ответы членов при этом сохраняются.
